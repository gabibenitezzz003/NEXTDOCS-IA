# Internacionalización (i18n)

El sistema soporta **español (`es`)**, **inglés (`en`)** y **portugués (`pt`)** en el portal completo y en los mensajes de error del backend.

## Frontend

- Diccionarios en `frontend/src/i18n/{es,en,pt}.ts`. El español es la base: `en` y `pt` deben tener exactamente las mismas claves (TypeScript lo exige con `typeof es`).
- `traducir(ruta, params)` resuelve `seccion.clave` con interpolación `{nombre}`. Si la clave no existe devuelve la ruta misma, lo que permite que algunas utilidades devuelvan claves y el componente las traduzca con `t(clave)`.
- `useIdioma()` (de `ProveedorIdioma`) expone `{ idioma, cambiarIdioma, t }`. Todo texto visible usa `t("...")`; nunca literales en el JSX.
- `localeActual()` / `formatearNumero()` formatean fechas y números según el idioma activo (`es-AR`, `en-US`, `pt-BR`). No usar `toLocaleString`/`Intl` con locale fijo.
- Enums del backend se muestran vía secciones del diccionario (`estadoInstancia.*`, `tipoNodo.*`, etc.): el valor del API no se traduce, solo la etiqueta.
- Selector de idioma en el login y en la topbar (`componentes/Idioma.tsx`).

## Persistencia y propagación

- El idioma elegido se guarda en `localStorage` (`nextdocs.idioma`) y, si hay sesión, en el perfil vía `PUT /api/v1/administracion/perfil/idioma`.
- Al iniciar sesión, `sesion.idioma` (campo de `SesionResModel`) prevalece sobre la preferencia local.
- Cada request lleva `Accept-Language: <idioma>` (interceptor en `api/cliente.ts`).
- Idioma inicial: perfil → `localStorage` → `navigator.language` → `es`.

## Backend

- `MensajesService` carga `resources/i18n/{en,pt}.json`. **No hay `es.json`**: la clave del diccionario es el literal español del `throw`, así los `throw new ExcepcionX("mensaje")` no cambian y los tests que asertan texto siguen valiendo.
- `ErrorHandler` resuelve cada mensaje con `Accept-Language` antes de responder; locale desconocido o clave faltante devuelven el texto original (español).
- Las claves pueden llevar `{0}`, `{1}`…: el resolvedor convierte la plantilla en patrón, extrae los valores del mensaje real y los reinjecta en la traducción. Para agregar un mensaje parametrizado nuevo no hay que tocar el `throw`, solo sumar la plantilla en `en.json`/`pt.json` con los mismos placeholders.
- Mensajes que no estén en el diccionario se devuelven tal cual (español). Cobertura inicial: autenticación, federación, OAuth, usuarios y respuestas del handler.

## Tests

- Las suites de Playwright fijan `locale: "es-AR"` en `playwright.procesos.config.ts` (las transversales lo heredan), porque `idiomaInicial()` toma `navigator.language` y el runner usa `en-US` por defecto.
